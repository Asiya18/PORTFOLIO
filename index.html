DocuMind — RAG Document Q&A

Jan – Feb 2026
Python · FastAPI · LangChain · GROQ · FAISS · ChromaDB
  • Problem: manually searching long PDFs is slow, and plain LLM chat without retrieval hallucinates facts it doesn't have.
  • Technology: LangChain for orchestration, GROQ API for generation, FAISS/ChromaDB for vector storage, FastAPI backend.
  • Implementation: ingests uploaded PDFs, chunks and embeds them into a vector store, retrieves relevant chunks per query before passing to GROQ with a custom prompt.
  • Result: diagnosed oversized-chunk overlap causing wrong-chunk retrieval; fixed it, measurably improving answer relevance. Added retrieval logging, cutting debugging time.
  • Real-world use: actively use it during exams to query study notes/PDFs for specific concepts instead of scrolling manually.
↳ hardest call: chunk size vs overlap tradeoff — too small lost context, too large diluted relevance.

CrawlMind — Web-Crawling RAG Chatbot

Jul – Aug 2026
Python · LangChain · Flask · Ollama · ChromaDB · BeautifulSoup
  • Problem: getting reliable answers from a website's content needs manual reading; most chatbots need pre-built knowledge bases or paid APIs.
  • Technology: BeautifulSoup for crawling, Sentence-Transformer embeddings + ChromaDB for semantic search, Ollama for local inference, Flask API layer.
  • Implementation: crawls and cleans content from any target URL, indexes it in ChromaDB, answers via a locally-hosted LLM — no external API dependency. Headless Flask POST API with LangChain memory across multi-turn chats.
  • Result: fully self-hosted RAG chatbot, zero per-query API cost, usable for headless integration with no UI dependency.
  • Real-world use: use it for my own job search — point it at a company's careers page or general info page and ask "any AI/ML openings right now."

Edrishti — Voice-Led Bus Guide

Mar – May 2026
Flutter · Python · Firebase · Raspberry Pi · BLE · STT/TTS
  • Problem: visually impaired commuters can't visually confirm which bus is arriving, and static schedules don't reflect real-time positions.
  • Technology: Raspberry Pi + BLE for real-time proximity detection, Firebase Firestore for live route data, STT/TTS for voice interaction.
  • Implementation: Raspberry Pi on each bus broadcasts live location over BLE; app confirms arrival in real time rather than relying on fixed schedules, then reads route/destination details aloud via TTS.
  • Result: fully voice-first, hands-free commute experience — speak your destination and get audibly guided until you reach your stop.
↳ hardest call: BLE range/reliability on a moving bus vs GPS polling cost — chose BLE for near-instant arrival confirmation.
